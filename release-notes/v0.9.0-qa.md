# v0.9.0 QA and first-use checklist

## Automated coverage

Run `pnpm run check`. Tests cover statement-specific partial/extra payments, original minimums at low balances, removing earlier payments, historical entries, overdue bill occurrences, variable invoices, card-funded subscriptions, refunds, reconciliation, storage failures, stale tabs, migration idempotence, backup validation, the actual transformed payment handler, and server rendering of all main pages.

Server rendering verifies component execution and markup, not mobile layout, native date pickers, focus movement, or real browser downloads. Those checks remain manual until browser access is available.

## Upgrade review (use a downloaded backup first)

1. Confirm the new version and that account balances and payment amounts are unchanged.
2. Review imported statements under Debts. Correct due dates/minimums; reassign older payments if the old automatic-cycle behavior placed them incorrectly. Remove unused incorrect statements only after their payments are reassigned.
3. Review bill occurrences and confirm actual amounts/dates. No older unpaid history can be inferred with certainty from legacy data; the app starts from available dates and flags imported assignments.
4. Check the payoff extra amount; existing values are intentionally retained.
5. Download a new backup and restore it in a separate disposable test browser profile, never over the only copy of real data.

## Manual browser/device acceptance

- At 320px, 390px, tablet, and desktop widths: no horizontal scrolling, clipped status, or overflowing date fields in every new modal.
- Check light/dark/system modes and all accents, including reconciliation textareas.
- Tab and Shift+Tab stay in each dialog; Escape closes it; focus returns to the opener. Check the mobile navigation sheet, Settings, and new financial dialogs.
- On iOS Safari and Android Chrome, open each date picker and save/reopen the selected local date.
- Log a minimum and another extra payment on the same day. Both remain on one statement; due date does not advance.
- Confirm a $90 actual invoice against a $100 estimate, pay $90, and verify completion. Repeat with a $120 invoice.
- Log a refund; confirm it reduces net spending without increasing income. Reconcile a balance and verify the reason/history.
- In two tabs, save in one and then try the other. The stale tab must not overwrite it.
- Verify backup download really produced a file, then verify restore confirmation/cancel and previous-state recovery with test data.

## Optional usability check — not a commercial launch

Ask a trusted volunteer to add an account, confirm a statement, log a payment and a refund, and explain the cash estimate without coaching. Record confusing wording or steps. No external outreach, analytics collection, Firebase migration, or commercial offer is part of this release.
